# Архітектура Movie Night

## 1. Контекст

**Проблема.** Компанія з 2–8 людей хоче подивитись фільм разом. Сьогодні це виглядає як 40 хвилин гортання
каталогів, суперечки в чаті та «давай ти обереш». Кожен вже бачив різне, і ніхто не пам'ятає, що саме.

**Користувачі.** Друзі, пари, співмешканці, які збираються на кіновечір офлайн або в Discord.
Майже всі заходять з телефона за посиланням чи QR, який їм кинули в чат.

**Головне, що має працювати з першого дня:** зібрати людей в одну кімнату, показати їм ту саму колоду фільмів,
яких вони ще не бачили, і знайти фільм, що сподобався всім.

**Чого не має статися ніколи:** запропонувати фільм, який хтось бачив і не хоче передивлятись; показати
одному користувачу чужу фільмотеку; отримати непередбачений рахунок за хмару.

## 2. Нефункціональні вимоги (з числами)

| Атрибут | Вимога | Як забезпечено / перевірено |
|---|---|---|
| Продуктивність | Колода з 20 фільмів збирається за ≤ 5 с (p95) для кімнати до 6 людей | Паралельні запити до TMDB (16 потоків), кеш деталей у пам'яті Lambda. Вимірюємо ~2 с у `scripts/e2e.py` |
| Свіжість стану | Інші учасники бачать голос/збіг за ≤ 3 с | Опитування `GET /rooms/{code}?deck=0` кожні 2 с, лише коли вкладка видима |
| Вартість | ≤ $5/міс при ≤ 1 000 MAU; $0, коли нікого немає | Lambda + DynamoDB on-demand + CloudFront; немає NAT і постійних серверів; AWS Budget з попередженням на $10 |
| Захист від зловживань | Помилка в клієнті не генерує безмежний рахунок | Throttling API Gateway: 50 rps, burst 100 |
| Безпека | Кожен запит до `/api/*` має валідний JWT з Cognito; користувач бачить лише свою фільмотеку й кімнати, де він учасник | JWT-авторизатор API Gateway (підпис, issuer, audience, expiry); ключ DynamoDB завжди будується з `sub`; перевірки учасника/ведучого в `rooms/service.py` |
| Секрети | Жодного ключа в репозиторії, образі чи коді | `.env` поза git; TMDB token у SSM SecureString; Lambda має право читати лише цей параметр |
| Зберігання даних | Кімнати не накопичуються | DynamoDB TTL: кімната видаляється через 2 дні |
| Відтворюваність | Друге середовище створюється однією командою | Уся інфраструктура в Terraform, стан у S3 з версіонуванням і блокуванням |
| Мобільність | Інтерфейс працює на екрані 360 px і з тачем | Mobile-first верстка, свайпи жестами, перевірено скриншотами 390×844 |

## 3. Рішення

### ADR-1. Модульний моноліт на одній Lambda
**Контекст:** маленька команда, 4 дні, домен ще рухається.
**Рішення:** один FastAPI-застосунок, поділений на модулі `users`, `movies`, `library`, `rooms`, `recommendations`.
Модулі звертаються один до одного лише через свій `api.py`. Всередині модуля шари йдуть так: `router → service → repository`.
Обидва правила перевіряє `import-linter` у `backend/.importlinter`.
**Наслідки:** один деплой і один набір тестів; агенту чи новій людині досить прочитати один репозиторій. Якщо колись
`recommendations` знадобиться 10× ресурсів, модуль можна винести в окремий сервіс: його інтерфейс уже є.

### ADR-2. Lambda + DynamoDB замість ECS + RDS
**Контекст:** бюджет «дуже маленький», навантаження нерівне (вечір п'ятниці проти ранку вівторка).
**Рішення:** Lambda (arm64, 1 ГБ) за API Gateway HTTP API; DynamoDB on-demand з однією таблицею.
**Чому не RDS:** Lambda з RDS мусить жити у VPC, а Lambda у VPC ходить до TMDB лише через NAT Gateway (~$32/міс постійно).
Сам RDS теж оплачується щогодини. Наші запити — це прості читання за ключем, joins не потрібні.
**Ціна:** холодний старт ~1 с на першому запиті; аналітичні запити незручні (для прототипу не потрібні).

### ADR-3. Купити автентифікацію
**Рішення:** Cognito managed login (пошта + Google), PKCE у SPA, JWT перевіряє API Gateway.
**Чому:** вхід — не наша відмінність. Помилки в хешуванні паролів та OAuth — найчастіша причина витоків.

### ADR-4. Опитування замість WebSocket
**Рішення:** клієнт опитує стан кімнати кожні 2 с. Колода завантажується один раз за раунд, далі приходить лише легкий стан.
**Чому:** 2–12 людей і NFR «≤ 3 с» опитування виконує. API Gateway WebSocket вимагав би таблиці з'єднань, розсилки
та обробки обривів. Кожен учасник пише лише у свій запис `MEMBER#`, тому одночасні свайпи ніколи не конфліктують.

### ADR-5. Letterboxd без API
**Контекст:** API Letterboxd видають лише за заявкою, а рекомендаційним і приватним проєктам прямо відмовляють.
**Рішення:** публічний RSS профілю (містить TMDB id та оцінку, ~50 останніх записів) плюс розбір файлу
експорту в браузері, де на сервер надсилаємо лише `{title, year, rating}`.
CSV імпортується пакетами по 40, щоб кожен запит вкладався в 29 с ліміту API Gateway.

### ADR-6. Рекомендації — пояснювана формула, а не ML
**Рішення:** `recommendations/scoring.py` — чисті функції:
- **виключення:** фільм бачив хтось, хто не хоче передивлятись;
- **кандидати:** TMDB recommendations для фільмів, які учасники оцінили на ≥ 3.5★, плюс discover за фільтрами;
- **оцінка** складається з:
  - кількості учасників, чиї улюблені фільми привели до цього кандидата;
  - збігу з жанровим профілем компанії (кожен учасник важить однаково);
  - рейтингу TMDB, зваженого кількістю голосів;
  - популярності.

Кожна картка показує причини: «Схожий на "Інтерстеллар" (фаворит — Анна)».
**Чому:** немає даних для навчання моделі; пояснення підвищують довіру; логіку покривають юніт-тести.

## 4. Модель даних (одна таблиця DynamoDB)

| PK | SK | Що | Власник |
|---|---|---|---|
| `USER#<sub>` | `PROFILE` | ім'я, email, маскот | users |
| `USER#<sub>` | `FRIEND#<sub>` | з ким був у кімнатах, скільки разів | users |
| `USER#<sub>` | `MOVIE#<tmdbId>` | фільм у фільмотеці: оцінка, `rewatch`, жанри, джерело | library |
| `ROOM#<code>` | `META` | ведучий, статус, фільтри, колода, раунд, обраний фільм, `ttl` | rooms |
| `ROOM#<code>` | `MEMBER#<sub>` | маскот, голоси `{movieId: bool}`, останній голос, `ttl` | rooms |

Стан кімнати (мета + усі учасники) — це один `Query` за `PK=ROOM#<code>`.

## 5. Що свідомо не робили

- Справжню оплату в продукті (на бонус — кнопка донату на ЗСУ).
- Пояснення рекомендацій через LLM: зайві затримка, гроші та ризики. Для цього вже є готовий шов —
  adapter у `recommendations`, якщо колись буде потрібно.
- Мікросервіси, черги, WebSocket: жодна NFR цього не вимагає.
